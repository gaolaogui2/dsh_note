# DeepSeek Harness 专题精读

## 阶段目标

前三个阶段已经建立全局概念、启动与请求主链，以及需求到领域的定位能力。第四阶段开始选择一个子系统，追踪它的职责、核心对象、状态、生命周期、扩展机制与验证证据，形成实现级理解。

```text
全局概念
→ 主链路
→ 领域定位
→ 单个专题的实现机制
→ 可由源码与测试验证的结论
```

本阶段不按目录遍历仓库，也不要求一次掌握全部专题。每次只研究一个边界明确的问题。

预期时间：每个专题 6～12 小时；Agent Runtime、Session Architecture 和 Web Architecture 通常需要 8～16 小时。

## 专题顺序

推荐按以下顺序展开，但真实需求可以改变顺序：

1. **Agent Runtime**：Inbox、Turn、Step、模型请求、Tool 调度与 Turn 结束。
2. **Session Architecture**：Session Events、消息投影、持久化、恢复、fork 与 compaction。
3. **Tool Runtime**：注册、作用域、模型呈现、Guard、执行调度与结果上下文。
4. **Capability Seam**：选择一个具体能力，追踪 Definition、Provider、Consumer 和部署替换。
5. **Cordis Lifecycle**：Context、Fiber、Service、inject、Effect、Event、Waterfall 与 Scope。
6. **Web Architecture**：Host、API、Typert、Client Runtime、Conversation Node 与 Slots。
7. **Distribution**：Profile、Bundle、Patch、Settings、Credentials、ACP 与 SDK。

推荐先精读 Agent Runtime。它连接 Session、System Prompt、LLM 和 Tool，是第二阶段请求主链的控制中心。Cordis 机制在遇到具体生命周期问题时回查，比脱离业务单独遍历底层实现更容易建立联系。

## 单专题精读方法

### 1. 确定研究范围

先写出一个具体问题，限制本轮阅读范围。

```text
专题：
核心问题：
包含的职责：
暂不研究：
预期时间：
```

问题应指向一个机制，例如“一次 Step 如何形成并执行”，而不是“读完 Agent 的所有代码”。

### 2. 建立静态结构

先读架构文档、对应 subsystem reference 和 package README，再进入源码。记录：

```text
事实拥有者：
Service Definition 或核心对象：
Provider：
Consumers：
运行组合入口：
```

这一轮只确认职责和依赖关系，不立即展开每个函数。

### 3. 追踪一条真实链路

选择一条最能代表该专题的正常路径：

```text
入口
→ 核心状态变化
→ Service / Event / Plugin 协作
→ 对外结果
→ 事实保存位置
```

随后补充最重要的异常或中断路径，不枚举所有分支。

### 4. 分清四类状态

| 状态类型 | 判断标准 | 常见载体 |
| -------- | -------- | -------- |
| Durable fact | 重启、恢复或回放后仍需存在 | Session Event / 持久存储 |
| Live state | 只描述当前进程中的运行状态 | Agent、Service、Registry |
| Scoped state | 只在特定 Context/Fiber 范围内有效 | Context、Fiber、Effect |
| Derived state | 可由其他事实重新计算 | Projection、Messages、UI model |

不能确认状态归属时，先找谁负责创建、修改、恢复和销毁它。

### 5. 理解生命周期与失败语义

```text
何时创建？
由哪个 Fiber 或对象持有？
何时可被 Consumer 使用？
取消、失败或卸载时如何收尾？
重启后依靠什么恢复？
```

重点理解所有权与清理关系，不追逐与专题无关的防御性细节。

### 6. 建立证据闭环

每个重要结论至少找到以下证据中的两类：

```text
声明：类型、Service Definition、Event Map 或配置格式
生产：创建状态、注册能力或写入事件的位置
消费：读取状态、调用能力或处理事件的位置
验证：unit test、snapshot、invariant 或真实示例
```

Agent Note 用于理解设计理由、替代方案和代价；当前源码、文档和测试用于确认实际行为。

## 单专题完成标准

一个专题达到以下程度即可结束本轮，不要求记住所有实现细节：

1. 能明确说出事实拥有者及其职责边界。
2. 能画出核心对象和相邻领域的关系。
3. 能跟踪一条正常运行链和一个关键失败或取消分支。
4. 能区分 durable fact、live state、scoped state 和 derived state。
5. 能指出主要扩展点及其生命周期所有者。
6. 每个核心结论都有源码、文档或测试证据。
7. 能说明当前设计获得的能力以及承担的复杂度。

本阶段的稳定路径：

> 具体问题 → 事实拥有者 → 核心对象 → 运行链路 → 状态与生命周期 → 扩展点 → 验证证据 → 设计取舍。

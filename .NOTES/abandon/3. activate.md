> 启动拼装 = 把 profile、bundle、patch、env、CLI args 合成最终 Cordis 插件树。

它类似 webpack 的配置整合阶段：

```
webpack config / plugin / loader / env
  -> final compiler config
  -> compiler 启动

dsh profile / bundle / patch / env
  -> final Cordis entry list
  -> Cordis Loader 挂插件树
```

## 1. 总链路

```txt
dsh --profile web
  -> apps/cli 解析 launcher 参数
  -> 找到 profile
  -> profile 声明要加载哪些 bundle
  -> bundle 提供 cordis.patch.yml
  -> profile patch / home patch / --patch 继续叠加
  -> 得到最终 Cordis entry list
  -> Cordis Loader 按 entry list 挂插件
  -> 插件注册 ctx.sessions / ctx.tools / ctx.llm / ctx.agents / ctx.agentLoop ...
```

一句话：

> 启动拼装就是把多层配置合成最终 runtime 插件树。

## 2. apps/cli

apps/cli 是 dsh 命令入口。

入口文件：

```txt
apps/cli/src/bin.ts
```

发布后对应：

```txt
apps/cli/lib/bin.js
```

`package.json` 里声明：

```json
{
  "bin": {
    "dsh": "lib/bin.js"
  }
}
```

apps/cli 的职责：

```txt
1. 解析 dsh launcher 参数
2. 选择 profile
3. 加载 env
4. 合成 bundle / patch layers
5. 启动 Cordis root Context
6. 把剩余 args 交给被启动的 app plugin
7. 处理 dump-config / plugin 管理 / 进程退出
```

它不是 agent runtime，不直接执行模型和工具。

## 3. CLI 参数模型

`bin.ts` 先执行：

```ts
const invocation = parseDshArgs(process.argv.slice(2), readVersion())
```

然后按 mode 分发：

```ts
switch (invocation.mode) {
  case 'profile':
  case 'plugin':
  case 'dump-config':
}
```

apps/cli 只解析 launcher 自己关心的参数：

```txt
--profile <name>
--patch <path>
--dump-config
--dump-default-config
-V / --version
web
plugin
```

其他参数不会解析，会原样放进：

```ts
invocation.args
```

例子：

```sh
dsh --profile web --resume abc
```

解析成：

```js
{
  mode: 'profile',
  profile: 'web',
  patches: [],
  args: ['--resume', 'abc']
}
```

`--resume abc` 不是 launcher 参数，它属于 web/headless app plugin。

规则：

```txt
launcher 参数放前面
app 参数放后面
```

## 4. profile

profile 是 1 次 dsh 运行选择的插件组合方案。

可以理解成：

> profile 决定这次启动用哪些 bundle，以及用户自己的 patch 怎么叠加。

当前内置 profile 有 2 个：

```txt
web
headless
```

定义在：

```txt
packages/boot/app-boot/src/profile.ts
```

大致是：

```ts
PROFILE_TEMPLATES = {
  web: ['@deepseek-ai/dsh-base', '@deepseek-ai/dsh-web-app'],
  headless: ['@deepseek-ai/dsh-base', '@deepseek-ai/dsh-headless'],
}
```

含义：

```txt
web
  base + web-app

headless
  base + headless
```

profile 目录在：

```txt
$DSH_HOME/profiles/<name>
```

里面主要有：

```txt
package.json
cordis.yml
cordis.patch.yml
pnpm-workspace.yaml
```

其中：

```txt
package.json
  保存 dsh.profile.bundles。

cordis.yml
  空 root，通常是 []。

cordis.patch.yml
  用户对这个 profile 的自定义 patch。
```

## 5. bundle

bundle 是可复用插件组合包。

例如：

```txt
@deepseek-ai/dsh-base
@deepseek-ai/dsh-web-app
@deepseek-ai/dsh-headless
```

bundle 不是单纯配置文件，它是 npm package。

它通过 `package.json` 声明自己提供哪个 patch：

```json
{
  "dsh": {
    "bundle": {
      "patch": "./cordis.patch.yml"
    }
  }
}
```

所以 bundle 由两部分组成：

```txt
package.json
  声明 bundle 元信息和依赖。

cordis.patch.yml
  真正描述要插入/修改/禁用哪些插件 row。
```

有些 bundle 还会有 `src/`：

```txt
src/
  这个 bundle 自己实现的运行时代码插件。
```

例如 `@deepseek-ai/dsh-web-app` 既提供 web patch，也实现 web runtime plugin。

## 6. cordis.patch.yml

`cordis.patch.yml` 是 Cordis 插件树的补丁层。

它描述的不是代码补丁，而是 runtime 配置变更：

```txt
插入 plugin row
覆盖某个 row 的 config
禁用某个 row
```

常见 row 字段：

```yml
- id: system-prompt
  name: '@deepseek-ai/dsh-system-prompt'
  config:
    persona: ''
  inject: [settings]
  disabled: false
```

字段含义：

```txt
id
  稳定 row id。后续 patch 靠它定位。

name
  要加载的插件包名。

config
  传给插件的配置。

inject
  声明依赖哪些 service。

disabled
  是否禁用，支持 !!js 表达式。
```

插入 row：

```yml
- insert:
    - id: my-plugin
      name: './my-plugin.ts'
```

覆盖 row：

```yml
- id: system-prompt
  config:
    persona: 'hello'
```

注意：

```txt
config 是整体替换，不是深度 merge。
```

## 7. patch 叠加顺序

最终配置来自多层 patch。

顺序是：

```txt
1. 每个 bundle 的 cordis.patch.yml
2. profile 自己的 cordis.patch.yml
3. home-level cordis.patch.yml
4. CLI --patch overlays
5. launcher 派生 patch，例如 telemetry switch
```

也就是：

```txt
base bundle
-> web/headless bundle
-> profile patch
-> home patch
-> --patch
-> final entry list
```

后面的层可以覆盖前面的 row。

## 8. base bundle

`packages/bundle/base/cordis.patch.yml` 是所有 profile 共享的基础插件清单。

它一次性 `insert` 大量基础 rows。

主要包括：

```txt
Cordis 基础设施
  timer / hmr

Harness core
  llm / session / agent / tools / system-prompt / agent-loop

模型适配
  agent-default-model / llm-deepseek / llm-pi-ai / llm-retry

Session 相关
  persistence / title / query / projection / telemetry / checkpoint

权限和沙箱
  subprocess / sandbox / approval / permission

工具
  bash / pwsh / fs / web / todo / subagent / workflow

压缩和 token
  token-meter / compaction / tool-result-pruner / spill

设置和凭证
  settings / credentials
```

base 的定位：

> 提供所有运行模式共享的 agent runtime 底座。

## 9. web-app bundle

`@deepseek-ai/dsh-web-app` 在：

```txt
packages/bundle/web-app
```

它的 patch 做几类事：

```txt
1. 覆盖 base 的部分配置
   system-prompt / hmr / tools / session-query 等。

2. 插入 web host 插件
   webserver / api-gateway / web-runtime / storage / workspace 等。

3. 插入浏览器 UI 插件
   ui-layout / ui-conversation / ui-tool / ui-settings 等。

4. 禁用 base 中一批 agent-plane 工具
   让 web session 通过 agent presets 组合自己的工具。

5. 插入 agent-presets
   每个 web session 按 preset 创建 agent 能力集。
```

web profile 本质：

```txt
base runtime + web surface overlay
```

## 10. headless profile

headless 表示无 UI 的一次性运行模式。

特点：

```txt
不启动 web 页面
不启动浏览器交互面
接收命令行 task
跑 agent
输出结果
退出
```

适合：

```txt
脚本
CI
自动化任务
命令行一次性调用
```

对比：

```txt
web       启动 Web 应用，用户在浏览器交互
headless  不要界面，命令行提交任务并等待结果
```

## 11. 最终产物

启动拼装的最终产物是：

```txt
final Cordis entry list
```

然后 Cordis Loader 按 entry list 挂插件。

插件挂载后才会出现：

```txt
ctx.sessions
ctx.tools
ctx.llm
ctx.agents
ctx.agentLoop
ctx.systemPrompt
```

所以：

```txt
apps/cli
  负责拼装 runtime。

Cordis Loader
  负责挂载插件树。

Harness plugins
  负责注册 agent runtime 能力。
```

一句话：

> 启动拼装阶段不跑 agent，它只决定这次 dsh runtime 由哪些插件组成。
